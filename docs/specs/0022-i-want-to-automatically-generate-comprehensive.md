## Context

Promoted from idea `IDEA-004` (I want to automatically generate comprehensive fish shell
and/or other shell completion files for the wt tool).

`wt` is a Click 8 CLI with a growing command surface (report/export/tasks/agenda/digest,
idea/spec/skills, …). Today there is **no** shell completion: users type every subcommand,
flag, project name, SPEC id, and idea selector by hand. Fish is the primary shell of interest;
bash and zsh should work too without a separate maintenance path.

Click 8 already ships shell-completion plumbing (`_WT_COMPLETE=<shell>_{source,complete}`)
for commands, options, and `click.Choice` values. What we lack is (1) a user-facing way to
print/install the script, and (2) custom `shell_complete` callbacks so high-value dynamic
values (projects, topics, states, SPEC/idea selectors, schemes, paths) complete as well.

## Goals / Non-goals

**Goals**
- Generate and install completion scripts for **fish, bash, and zsh** from the live Click
  command tree (no hand-maintained completion files that rot).
- Broad **dynamic** completion wherever it helps: projects, topics, TODO/idea states,
  priorities, SPEC/outbound ids, idea selectors, export schemes/artifacts, outbox targets,
  task selectors, and path arguments.
- A thin CLI: `wt completion <shell>` prints the script; `wt completion install --shell
  <shell>` writes the conventional user path (overridable with `--dest`).
- Completers **fail soft** — missing org/config/data must yield an empty candidate list, never
  crash the shell prompt.

**Non-goals**
- New third-party completion libraries (`argcomplete`, etc.).
- Network-backed completion (live JIRA search, remote repos).
- Rewriting the CLI framework away from Click.
- Guaranteeing perfect selector matching for every fuzzy heading substring — prefix-filtered
  IDs / keys / known values are enough for v1.

## Decision

Ship Click 8 built-in shell completion for fish/bash/zsh, exposed via a new `wt completion`
command group that prints or installs the generated script. Put script emit, install-path
conventions, and shared dynamic `shell_complete` callbacks in a new `src/wt/completion.py`
module; wire callbacks onto the relevant options/arguments in `src/wt/cli.py`. No new
dependencies — `click>=8` is already required.

## Design

### Mechanism

Click’s env-var protocol remains the engine:

- `_WT_COMPLETE=<shell>_source wt` → completion script source
- `_WT_COMPLETE=<shell>_complete wt` → candidate list during tab-complete

`wt completion` is a friendly wrapper around the same machinery (prog name `wt`, complete var
`_WT_COMPLETE`). Document the env-var form in the README as a fallback.

### CLI (`src/wt/cli.py`)

New group:

```
wt completion bash|zsh|fish          # print script to stdout
wt completion install --shell <s> [--dest PATH] [--force]
```

Default install destinations:

| Shell | Default path |
|-------|----------------|
| fish  | `~/.config/fish/completions/wt.fish` (honors `$XDG_CONFIG_HOME`) |
| bash  | `~/.local/share/bash-completion/completions/wt` (honors `$XDG_DATA_HOME`) |
| zsh   | `~/.local/share/zsh/site-functions/_wt` (honors `$XDG_DATA_HOME`) |

`--dest` overrides. Install creates parent dirs as needed; is **idempotent** when the file
already matches; refuses to overwrite a divergent unmanaged file unless `--force`. Scripts
are stamped with a `# generated by wt completion (SPEC-0022)` marker so refreshes of our
own files don't require `--force`.

### Module (`src/wt/completion.py`)

- `source_script(shell) -> str` — emit Click’s completion source for `wt` / `_WT_COMPLETE`.
- `default_install_path(shell) -> Path` — table above (XDG-aware where applicable).
- `install(shell, *, dest=None, force=False) -> Path` — write script; return path written.
- Shared completer helpers returning `list[click.shell_completion.CompletionItem]`, each
  wrapped to catch load errors and return `[]`:

  | Target | Source |
  |--------|--------|
  | `--project` | `known_projects(cfg)` |
  | `--epic` | `known_epics(cfg)` |
  | `--state` (tasks/add) | `org_todo_keywords` |
  | `--state` (ideas) | `org_idea_keywords` |
  | `--priority` | `click.Choice(["A","B","C"])` |
  | `--format` | existing `Choice(["csv","json"])` |
  | `--by` | facet axes from mappings + `project`/`topic` |
  | `--from-idea` | open idea IDs (prefix filter) |
  | `spec generate` arg | internal `SPEC-NNNN` ids under `specs_dir` |
  | `spec export` arg | outbound ids under data-dir outbox |
  | `--scheme` / `--emit` | `available_schemes()` + artifact names |
  | `--target` | `outbox_targets` keys |
  | `state`/`done` selector | open task `:ID:`s / topic_keys (prefix-filtered) |
  | `map` raw topic | keys of `mappings.yaml` (no transcript re-ingest) |
  | path options (`--file`, `--to`, `--dest`, ingest rawfile) | `click.Path` |

### README

Documents print, install, and the `_WT_COMPLETE` env-var form under Commands → Shell
completion.

## Alternatives considered

- **Hand-written fish (or bash/zsh) scripts** — rejected; they rot as the CLI grows and
  duplicate what Click already derives from the command tree.
- **`argcomplete` / other third-party completers** — rejected; Click 8’s built-in support is
  sufficient and keeps the dependency set small.
- **Env-var-only UX (no `wt completion` command)** — rejected; print + install is the chosen
  ergonomic surface (fish-first install path).

- [x] Completers return an empty list (do not raise) when org/config/data is missing or
      unloadable.

- [x] Default no-arg `wt` dashboard behavior is unchanged; existing CLI tests stay green

## Test plan

- **Automated tests** (`tests/test_completion.py`):
  - `source_script` / `wt completion <shell>` for each shell contains `_WT_COMPLETE` and `wt`.
  - `install` writes default path under a tmp HOME / XDG override; second install is a no-op;
    divergent file without `--force` errors; with `--force` overwrites.
  - Dynamic completer unit tests with injected tmp `cfg` (mappings → projects; ideas.org →
    idea IDs; `docs/specs` → SPEC ids; outbox → outbound ids; schemes registry → names).
  - Soft-fail: completer with broken/missing paths returns `[]`.
- **Manual verification:**
  1. `uv run wt completion fish | head` shows a fish `complete` / `_wt_completion` script. ✓
  2. `uv run wt completion install --shell fish --dest /tmp/wt-test.fish` writes the file. ✓
  3. `_WT_COMPLETE=bash_complete COMP_WORDS="wt " COMP_CWORD=1 uv run wt` lists top-level
     commands including `completion`. ✓ (interactive fish tab not required in CI)
- **Regression guard:** `uv run pytest` → 227 passed; `uv run wt` still prints today +
  this-week dashboard. ✓
